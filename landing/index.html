The same event, three representations — one framework behind them.

What the detector sees

Simulated single-particle events, rendered from the same graph datasets the models train on. Each point is a struck photomultiplier tube, coloured by collected charge; the Cherenkov cone intersects the tank wall as a ring. The electron ring is diffuse because the shower scatters, the muon ring sharp because the track is straight — that difference is what a particle-identification network learns.

Drag to rotate · the view turns about the detector axis on its own. Tank: 32.4 m radius, 33 m half-height.

The framework at a glance

One entrypoint

Every family runs through the same main.py and the same engine hierarchy. No per-family fork of the training code.

Configuration, not code

Hydra composes a run from config groups. Swapping a model, dataset or optimiser is a YAML line, not a patch.

Optional stays optional

The base install runs the image family with no PyTorch Geometric and no wandb. CI proves that boundary on every commit.

Reproducible runs

One top-level seed threads through samplers and distributed training; a deterministic mode makes two runs bit-identical.

A run is a composed configuration

A top-level config names a model, a dataset, an engine and a list of tasks. Hydra assembles them, and any value can be overridden from the command line — so a hyper-parameter scan needs no new file.

Read the quickstart 
# train a graph attention network for particle ID
python main.py \
  --config-path tutorial/config/caverns/main \
  --config-name gat_classification \
  'hydra.searchpath=[file://tutorial/config/caverns]'

# same model, different learning rate and 40 epochs
python main.py \
  --config-path tutorial/config/caverns/main \
  --config-name gat_classification \
  'hydra.searchpath=[file://tutorial/config/caverns]' \
  tasks.train.optimizers.lr=1e-4 tasks.train.epochs=40

# print the fully composed config and exit
python main.py --config-name resnet_train -c job
